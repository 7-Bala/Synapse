# Build Sequence

This document defines the strict vertical implementation sequence for Phase 3. We are abandoning horizontal UI layout development. No slice begins until the preceding slice is functionally complete and integrated end-to-end.

## The Sequence

### 1. Transport Layer (Infrastructure)
- **Scope**: Introduce FastAPI and WebSockets to `backend/api/app.py`. Wire it to `EventBus` and `Orchestrator` without modifying the core logic.
- **Success Criteria**: A frontend client can connect and receive live events generated by running a simulation script.

### 2. Execution Store (State)
- **Scope**: Implement `useExecutionStore` (Zustand) that parses WebSocket events and maintains the `ExecutionGraph` and `Blackboard` states in memory.
- **Success Criteria**: The store accurately reflects the backend state in the browser console.

### 3. Execution Graph (Visual)
- **Scope**: Render the `ExecutionGraph` dynamically based on the store.
- **Success Criteria**: Nodes appear, change color, and complete automatically as the backend Orchestrator ticks.

### 4. Execution Inspector (Detail)
- **Scope**: Clicking a node in the Graph opens the Inspector.
- **Success Criteria**: Displays the raw prompt, reasoning, and token telemetry for the selected `LiveSpecialistOutput`.

### 5. Replay Timeline (Time Travel)
- **Scope**: Introduce the global scrubber.
- **Success Criteria**: Dragging the scrubber fetches historical ticks and forces the Graph and Inspector to revert to that state.

### 6. Blackboard (Memory)
- **Scope**: Implement the live Blackboard explorer panel.
- **Success Criteria**: The memory JSON updates in real-time, flashing diffs as the Orchestrator ticks.

### 7. Consensus (Alignment)
- **Scope**: Implement the Consensus Explorer for nodes that require committee voting.
- **Success Criteria**: User can inspect dissenting opinions and final resolution for a consensus node.

### 8. Validators (Security)
- **Scope**: Expose blocked actions in the Validator Console.
- **Success Criteria**: User can read why an action was blocked and emit an "Override" command that resumes the execution.

### 9. Evidence (Data)
- **Scope**: Build the Evidence Browser to trace the provenance of data.
- **Success Criteria**: User can click a citation in the Inspector and view the raw retrieved document.

### 10. Evaluation (Benchmarking)
- **Scope**: Build the Evaluation Lab.
- **Success Criteria**: Compare two completed runs side-by-side against a golden dataset.

## Rule of Progression
Do not move from step N to step N+1 until step N is fully functioning end-to-end. If the backend is lacking a feature for step N, implement the backend feature first. No UI placeholders.
